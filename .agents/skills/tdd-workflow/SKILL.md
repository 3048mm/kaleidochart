# TDD & Documentation Workflow Skill

## Metadata
name: tdd-workflow
description: 設計(doc) -> テスト(tests) -> 実装(src) のサイクルを厳格に守り、プロジェクトの品質と保守性を担保するためのスキル。

## Instructions

あなたは Antigravity として、このプロジェクトでのあらゆる開発作業において以下の TDD 手順を厳守してください。

### 1. ドキュメント第一主義 (Doc First)
- 機能追加や変更を行う前に、必ず `doc/` 配下の該当する仕様書（`backend_specification.md` 等）を更新してください。
- 実装中に仕様の変更が必要になった場合は、コードを書き進める前にドキュメントにその旨を反映させてください。

### 2. テストの作成 (Write Tests)
- 実装を開始する前に、期待される動作を検証するためのテストコードを作成してください。
- 既存のテストスイートに追加するか、新しいテストファイルを作成します。
- この時点では、テストが「失敗（Red）」することを確認してください。

### 3. 最小限の実装 (Implementation)
- テストをパスさせるために必要な最小限のコードを記述します。
- 過度な抽象化や「将来必要になるかもしれない機能」の追加は避けてください。
- テストが「成功（Green）」することを確認します。

### 4. リファクタリング (Refactor)
- コードの可読性を高め、重複を排除するためにリファクタリングを行います。
- リファクタリング後もテストが成功し続けていることを確認してください。

### 5. 進捗管理
- `task.md` を使用して、現在のステップ（設計中 / テスト作成中 / 実装中）を明確に記録してください。
- ユーザーに報告する際は、どのテストが追加・実行されたかを明記してください。
