# 自動バックテスト最適化 (Optuna) マニュアル

本ドキュメントは、システムトレードにおける戦略の「パラメータ探索（ベイズ最適化）」を自動化し、実運用に最適なスクリーナー条件を探るためのガイドラインです。

## 1. 概要
`stocktool` のバックテスト機能は、通常 `backtest_config.toml` に記載された固定パラメータの有効性を 1 回テストするものです。
これをさらに推し進め、**「機械学習機能（Optuna）」を用いてパフォーマンスが高くなるパラメータの組み合わせを自動的に探索・最適化**するのが本機能の目的です。

### 1.1 最大の特徴
1. **中断＆再開 (Resume) 対応**
   - 探索結果は `data/optimization_trials.db` に常時記録されています。学習の途中で強制終了しても、次回起動時に「続き」から賢く再開します。
2. **ブル＆ベア相場によるクロス検証 (マルチ期間学習)**
   - 2022年（下落・ベア相場）と2024年下半期〜（強気・ブル相場）という**真逆の相場環境**でのバックテストを同時並行で行います。片方だけに過剰適合したカーブフィッティング・パラメータを見破り、「どのような相場でも生き残れるパラメータ」をあぶり出します。
3. **資産成長×DD抑制×検出件数の実用帯 (2026-07-07 再設計)**
   - スコアの主指標は **期間CAGR（複利での資産成長）** で、これを最大ドローダウンのペナルティで割ります（＝資産を伸ばしつつ DD を抑える方向へ最適化。実質 Calmar 型）。加えて、有限資産で実際に売買できるよう、1日あたりの検出件数が「多すぎず少なすぎず」の実用帯（`detect_band`）から外れると係数で緩やかに減点します。

## 2. 自動最適化の実行方法

用意されている専用のバッチスクリプトをダブルクリックするか、ターミナルから実行します。

### ステップ 1: 最適化プロセスを走らせる
プロジェクトルート（`stocktool/`）直下にある `run/` フォルダ内のスクリプトを実行します。

```bash
# ターミナルから実行する場合
.\run\run_optimization.bat
```

デフォルトでは `B_theme_momentum` の戦略に対して、**100回のパラメータ探索**を実行します。
※内部的には `backend/optimization_runner.py` が呼び出されており、手動で以下のようにカスタマイズすることも可能です。

```bash
# 特定の戦略を指定し、探索回数を 500 回にする場合
python backend/optimization_runner.py --strategy B4_rs_trend_with_theme --trials 500
```
**対象にできる戦略:**
`backtest_config.toml` 内の `[[strategy]]` の `name`（フルネーム、例: `B4_rs_trend_with_theme` や `A_momentum_breakout` など任意の定義名）を指定します。
(従来の短縮コード `A`, `B1` 等もプレフィックス一致で自動的に解決されます)

### ステップ 2: 探索結果を可視化する (ダッシュボード)
最適化が走っている最中、または完了した後に、別のターミナルを開いて以下のスクリプトを実行します。

```bash
.\run\run_optuna_dashboard.bat
```
その後、ブラウザで `http://localhost:8080/` にアクセスしてください。

**ダッシュボードでの注目ポイント**:
* **History (学習推移)**: 右肩上がりになっていれば、AIが「より良いスコアを出せるパラメータの法則」を見つけ出し、徐々に優秀な結果を生んでいる証拠です。
* **Hyperparameter Importance (重要度分析)**: 「どのパラメータの数値を弄ると、最もパフォーマンスに直結するのか（影響力が高いのか）」をパーセンテージで教えてくれます。あまり変化がないパラメータについては切り捨て、影響力の高いパラメータに絞って探索範囲を限定すると、さらに優秀な結果が見つかります。

## 3. 動作パラメーターのカスタマイズ (開発者向け)

探索パラメータのレンジ（範囲・刻み幅）やマルチ期間設定は、**`backtest_config.toml`** に一元定義されており、Pythonコードの変更は不要です。

### 3.1 探索パラメータの追加・変更について
各 `[[strategy]]` ブロックの下の **`[strategy.optimization]`** サブセクションで、探索するパラメータの「型」「範囲」「刻み幅」を定義します。

#### 記法一覧

| 型 | TOML記法 | 用途 |
| :--- | :--- | :--- |
| 連続値 (float) | `{ type = "float", min = 1.0, max = 5.0, step = 0.5 }` | RSランク閾値、乖離%、ADR% 等 |
| 整数 (int) | `{ type = "int", min = 0, max = 1, step = 1 }` | トレンドテンプレートON/OFF 等 |
| 選択肢 (categorical) | `{ type = "categorical", choices = [1e8, 5e8, 1e9] }` | 時価総額フィルタ、True/False 等 |

#### 変更例

例えば、戦略 D（EMA21 Pullback）で RSランクの下限を `0.50〜0.90` から `0.70〜0.95` に絞り込むには：

```toml
# backtest_config.toml

[[strategy]]
name = "D_ema21_pullback"
# (中略: 通常の実行で使う初期値・固定パラメータ)
min_rs_ratio_rank_e21 = 0.7

# 最適化探索範囲を strategy 内に内包する
[strategy.optimization]
# 変更前: min = 0.50, max = 0.90
# 変更後: より厳しい範囲に絞り込み
min_rs_ratio_rank_e21 = { type = "float", min = 0.70, max = 0.95, step = 0.05 }
```

新しいフィルタ条件（例: 出来高急増 `min_vol_surge_21`）を最適化対象に追加する場合：

```toml
[[strategy]]
name = "D_ema21_pullback"
# (中略)

[strategy.optimization]
# 既存のパラメータ...
min_dist_21ema_pct   = { type = "float", min = -4.0, max = -1.0, step = 0.5 }

# 新規追加: 出来高急増も探索対象にする
min_vol_surge_21     = { type = "float", min = 0.5, max = 3.0, step = 0.5 }
```

`[strategy.optimization]` に書かれていないパラメータ（例: `description` 等）は、`[[strategy]]` セクションのデフォルトのパラメータがそのまま継承されるため、変更せずとも動作します。

### 3.2 マルチ期間設定の変更
最適化時のバックテスト対象期間（ベア／ブル相場）も `backtest_config.toml` で管理しています。

```toml
[optimization_periods]
periods = [
    { start = "2022-01-01", end = "2022-12-31", label = "Bear 2022" },
    { start = "2024-06-01", end = "2025-12-31", label = "Bull 2024-25" },
]
```

新しい期間を追加したい場合（例: 2020年のコロナショック期間）は、`periods` 配列に要素を追記するだけです。

### 3.3 ペナルティなどの調整について
「実運用ではやはり1日20件以上ヒットすると手動で買えないので除外したい」「ドローダウンは絶対-15%未満に抑えたい」といった運用ポリシーによる制約は、`optimization_runner.py` の `calculate_custom_score` 関数内を調整します。

**現在のスコア構成（2026-07-07 再設計）:**
* **主指標＝期間CAGR**（複利での資産成長・年率化）。「1トレードの期待値」ではなく「資産をどこまで伸ばせるか」を評価します。
* **DDペナルティ**: 最大ドローダウンが `max_allowed_dd`（戦略ごとに設定。攻撃的B系=35、VCP/E系=20 等）を超えると、超過分の2乗で急激に減点（＝CAGR を割る。実質 Calmar 型）。
* **検出件数の実用帯**: 1日あたり検出件数が実用帯 `detect_band=(lo=1, hi=12, floor=0.4)` から外れると係数で減点（`[optimization_pruning]` で調整可）。多すぎ（有限資産で買い切れない）も少なすぎ（枠が遊ぶ）も抑制。
* **勾配ゲート**: トレード5件未満は足切り（トレード数に応じた勾配付き）。

この基準を厳しくすることで、より「堅実で実運用に適した究極のパラメータ」をAIに探させることが可能になります。

### 3.4 最適化結果の適用 (Copy-Paste)

最適化が完了した、あるいは途中の優秀な Trial（試行）の結果を実用のスクリーナー条件に反映させるには以下の手順が最も効率的です。

1.  **Dashboard からコピー**:
    - Optuna Dashboard の各 Trial 詳細画面の上部にある **"Note"** 欄に、そのまま `.toml` に貼り付け可能な `key = value` 形式のパラメータセットが表示されます。
    - また、User Attributes セクションの `params_toml` からも同様のテキストを確認できます。
2.  **コンソールからコピー**:
    - `optimization_runner.py` の実行終了時に表示される `[TOML Params for copy-paste]` セクションのテキストをコピーします。
3.  **反映**:
    - コピーした内容を `backend/backtest/backtest_config.toml` の該当する `[[strategy]]` セクション、または `screener_presets.toml` に貼り付けることで、最適化されたパラメータを即座に利用できます。
