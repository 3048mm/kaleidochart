# バックテスト自動最適化（パラメータ探索）機能 提案書

## 1. 概要
スクリーナー条件に基づき、ストラテジー（B, D, F）の最適なパラメータを自動的に探索・最適化するシステムを構築します。
機械学習領域で広く利用されているハイパーパラメータ最適化フレームワーク **Optuna (オプチュナ)** の導入を提案します。

## 2. 要求事項への対応と実現性（Feasibility）

### ① 途中中断と復帰（レジューム機能）
- **実現性**: 高
- **提案**: Optuna は探索履歴（Study）を SQLite データベースに保存できます。プロセスが強制終了されたり、PCを再起動した場合でも、DBを指定してプロセスを起動するだけで、前回の続きから自動的に探索を再開します。

### ② ベース戦略（B, D, F）とスクリーナー条件の動的追加・削除
- **実現性**: 高
- **提案**: スクリーナーの各条件（`min_market_cap`, `min_adr_pct_21`, `max_sma50_atr_mult` など）を「探索空間（Search Space）」として定義します。
Optuna の `suggest_float` や `suggest_categorical` などのAPIを使えば、実行時に「どの条件を使うか（オン・オフ）」や「そのしきい値」を動的に生成できます。今後スクリーナー条件が増えた際も、探索対象に追加するだけで自動的にパラメーターの組み合わせをテストさせることが可能です。

### ③ 効果が高くなる方向への予測・自動調整（ベイズ最適化）
- **実現性**: 極めて高（標準搭載）
- **提案**: Optuna の中核アルゴリズムである **TPE (Tree-structured Parzen Estimator)** は、過去のバックテスト結果（勝率や累積利益のスコア）を学習し、「次はどのパラメータを試せばスコアが良くなりそうか」を確率的に予測（ベイズ最適化）して次の検証パラメータを決定します。ランダム検索や総当たり（グリッドサーチ）に比べて圧倒的に効率よく最適解にたどり着きます。

### ④ 履歴保存・推移のトレースと可視化
- **実現性**: 高（標準ツールで実現可能）
- **提案**: Optuna 公式の可視化ツール **Optuna Dashboard** を活用します。
  - Webブラウザ上で、最適化の推移（Optimization History Plot）
  - どのパラメータが最も結果に影響を与えたか（Parameter Importance）
  - パラメータ間の相関関係（Parallel Coordinate Plot）
  などをリアルタイムで美しいグラフとして視覚化できます。

## 3. システムアーキテクチャ案

1. **探索エンジン (`optimization_runner.py`)**: 
   - `optuna` のStudyを作成し、Trial（1回のバックテスト条件）を発行。
   - 発行されたパラメータで既存のバックテスト（シミュレーター）を呼び出し、結果スコア（例: リスクリワード・累積利益・ドローダウンなどを加味した総合スコア）をOptunaに返す。
2. **履歴DB (`optimization_history.db`)**:
   - SQLiteを使用して全Trialのパラメータと結果スコアを記録（現状の `stocktool.db` とは分けて軽量に管理）。
3. **可視化サーバー (`optuna-dashboard`)**:
   - バックグラウンドで起動しておき、Webフロントエンドとは独立したポート(`http://localhost:8080`等)で結果の推移を確認。

## 4. 進め方のステップ（別スレッドでの実装推奨）

1. **フェーズ1: 基盤構築**
   - `optuna`, `optuna-dashboard` のインストール。
   - `backtest_runner.py` のシミュレーション部分を、引数（パラメータ辞書）を受け取ってスコアを返す純粋な関数としてリファクタリング。
2. **フェーズ2: 目的関数（Objective）と探索空間の設計**
   - 「累積利益が高いがドローダウンも大きい」設定を避けるため、シャープレシオのような総合評価スコアを設計。
   - Strategy B, D, F 用のベースパラメータ探索範囲（最小・最大値）と、条件オン/オフの確率を定義。
3. **フェーズ3: 探索実行と分析**
   - 初回テスト（100件程度のTrial）を実施し、Optuna Dashboard で結果を確認。
   - 「無駄な条件」や「効いている条件」を抽出し、スクリーナーそのものの改善にフィードバックする。
