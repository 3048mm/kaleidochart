## 1. 背景と目的

2026-07-11 の型3（シナリオテスト）で、e4 のイベント版 E1/E2（ピボットクロス＋ドライアップ込み）は
コンセプト値・最適化ベストのいずれでもリターンがマイナス（PF 0.71〜1.27、SPY +43%に対し大敗）だった。
一方、E2 のジョブ定義バグで誤って実行されていた**旧・状態版**（`E2_vcp_basic` study、is_vcp_breakout を
使わない素朴な min_/max_ フィルタ）が +65%・PF 3.66・DD 8% と圧倒的に良かった（切り分けテストで確認済み）。

原因分析（会話でユーザーと確認済み）:
- 型1（スクリーン条件最適化）が求める「シグナルの独立性」問題は、e3 のイベント化ではなく
  2026-07-05 の「同一銘柄は exit まで再エントリー禁止」ブロックで**既に測定器側で解決済み**だった
- e3 のイベント化は製品（フロントに出すスクリーン定義）を変えてしまい、型3のトレード方式
  （ブレイク日の引けで追いかけ買い）と噛み合わず、実運用の成績を悪化させていた
- 状態版（「収縮した土台にいる銘柄を監視・仕込む」）はフロント用途としても自然で、型3の実測でも優位

**方針**: E1/E2 の製品定義を状態版へ戻し、e4 で確立した「質ゲート」（収縮度・出来高ドライアップ）を
状態条件として移植する。型1で再最適化 → 型3で受け入れ評価 → フロントプリセットへ、という当初の
連鎖（型1=手段／型3=受け入れ試験／フロント=成果物）に一本化する。

**成功条件**: E1/E2 が状態ベースの min_/max_/is_ フィルタで定義され、e3323e8 時点の状態版に
出来高ドライアップ条件（`max_vol_surge_21`）が加わっている。全テスト green。型1サニティで
クラッシュなく妥当な件数が出る。

## 2. スコープと設計判断

- `doc/issue_list.md` に非互換の記録

### 2.2 変更しないこと（確定した設計判断）

| 論点 | 判断 |
|---|---|
| `filter_vcp_breakout` / `is_vcp_breakout` の特殊フィルタ本体 | **削除しない**。E1/E2 が使わなくなるだけで、テスト済みの汎用イベント検出として温存（RRG 等の他の未使用フィルタと同じ扱い）。「ブレイク通知」用途で将来使う可能性を残す |
| E1/E2 の `name`（TOML の `[[strategy]] name`） | **変更しない**（`E1_vcp_breakout_mid` / `E2_vcp_breakout_52w` のまま）。`scenario_batch_jobs.toml`・doc 等の参照を壊さないため。「breakout」の名称が実態（状態版）と乖離するのは issue_list に低優先度で記録し、E2_vcp_basic の命名逆転 issue と合わせて後日クリーンアップ |
| 期間ファミリーの区別（E1=中期／E2=52週） | **維持**。e3323e8 は E1/E2 とも `min_dist_52w_high_pct` で未分化だったが、e3/e4 で確立した「E1=63日高値近傍／E2=52週高値近傍」の区別を状態版でも踏襲する（E1: `min_dist_63d_high_pct`、E2: `min_dist_52w_high_pct`） |
| ドライアップ条件の形 | e4 は「前日の」`vol_surge_21`（イベントの前提が必要）だったが、状態版はイベントでないため**当日の** `max_vol_surge_21` として移植（急な出来高スパイクが無い＝土台が静かという意味は同じ） |
| 新規 T3 カラム | 不要。全て既存カラム（`vcr`, `dist_63d_high_pct`, `dist_52w_high_pct`, `vol_surge_21`, `adr_pct_21`, `up_down_vol_ratio_50`）の state 版 min_/max_ 参照のみ |
| 型1の再最適化（12時間） | 本計画のスコープ外。ユーザー実施。既存 study は非互換なので退避が前提（従来と同じ運用） |
| 型3の再評価 | 本計画では簡易サニティのみ（baseline 値、少数 MC run）。本格評価は型1再最適化後にユーザーが実施 |
| コミット/プッシュ | ワークツリー自ブランチへのコミットは許可済み。push/PR は都度指示待ち |

## 3. 変更内容

### 3.1 E1/E2 を状態版へ（backtest_config.toml）

共通の質ゲート（e3323e8 ベース + 新規ドライアップ）:
- `is_trend_template = true`
- `max_vcr`（収縮度。E1=0.7 / E2=0.65、e3323e8 を踏襲）
- `max_adr_pct_21 = 1.5`（値幅の静けさ）
- `max_vol_surge_21`（**新規**。出来高ドライアップ。baseline 1.2、e4 の `base_vol_dry_max` 調整値を移植）
- `min_up_down_vol_ratio_50 = 1.5`（買い集め傾向）
- `min_market_cap = 1e9`（旧 E2_vcp_basic の好成績と同じ水準）
- 期間別の高値近傍: E1 `min_dist_63d_high_pct = -15.0` / E2 `min_dist_52w_high_pct = -10.0`
- E2 のみ `is_close_gt_ema63 = true`（e3323e8 を踏襲）
- 両方に `max_allowed_dd = 20.0`（TOML 冒頭の VCP=20 基準に統一。旧 E2 は 15.0 だったが基準統一のため緩和）
- 両方に `min_avg_hits_per_day` / `min_hit_rate_pct` の pruning ゲート（E1 は e3323e8 で未設定だったが、E2 と揃える）

`[strategy.optimization]` は各パラメータに探索レンジを設定（`max_vol_surge_21` は e4 の `base_vol_dry_max`
レンジ 0.7〜1.5 を踏襲、他は e3323e8 のレンジを復元）。
