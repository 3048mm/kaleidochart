## 1. 背景と目的

### 課題の前提が誤っていた

課題リストは「**未調整の株式分割が 299 件残っている**」としていたが、
2026-08-04 の全数調査で**これは誤り**と判明した。

現在の検出は「前日比が 0.61 以下 または 1.79 以上」だけを見ており、
**大きな値動きを全部拾っているだけ**である。モメンタム系スクリーナーの母集団
（小型株・バイオを含む）では ±50〜70% の単日変動は日常的に起きる。

### ベースライン（2026-08-04 実測 / Parquet 全期間・active 銘柄）

```
アノマリー総数  1,081件 / 504銘柄
  週次監査の射程内（SQLite 直近730日）   306件
  射程外（それより古い）                775件  ← 72% が検出できていない
```

内訳（実測）:

| 分類 | 実体 | 対応 |
| :--- | :--- | :--- |
| **実際の値動き** | `CLDX` 治験失敗 / `MDGL` 治験成功 / `NKTR` データ失望 / `PCG` 破産申請 / `NVAX` 治験失敗 | **正常なデータ。対応不要** |
| **低位株のティック振動** | `ATLX` が 0.75↔1.50 を何年も往復（27件）。`RCAT` `EXOD` `MRDN` も同型 | 分割は一度きりで不可逆なので分割ではない |
| **市場全体の急落日** | 2020-03-09 に34銘柄、03-18 に16銘柄、03-16 に12銘柄（COVID） | 108件。個別の分割ではない |
| **仮想テーマ指数** | 構成銘柄の入れ替えで段差が出る。**加えて構成銘柄の未調整分割を継承する**（リターン連鎖のため） | 43件。テーマ自体は分割しないが、構成銘柄の分割は伝播する |
| **本物の未調整分割** | `SOXS` `WBX` など | **ごく少数** |

### 目的（成功条件）

アノマリー報告を**実際に対応が必要なものだけ**にする。
現状は 1,081件のうち大半がノイズで、本物が埋もれている。
**「報告が出たら見る」が成立する状態**にすることがゴール。

### 2.2 変更しないこと（確定した設計判断）

| 論点 | 判断 | 理由 |
| :--- | :--- | :--- |
| 売買代金比を主判定にする | **しない。補助に留める** | 有効なのは極端な比率（≤0.22 / ≥4.0）だけ。**1:2 前後の帯では機能しない**ことが実測で判明した。暴落は出来高が1.5〜3倍に跳ねるため代金比が 0.5〜2.0 に収まり、分割と区別できない（`DIN` `ADAM` `BBAI` の COVID 暴落を「分割」と誤判定した） |
| Yahoo の分割記録を遡及適用して現在の汚染を直す（旧案②） | **やらない** | 497銘柄を全数照会した結果、**日付が一致したのは 22/1,035件、比率まで一致したのは 1件のみ**。実売買しうる水準（>$5・>$1M/日）では 468件中6件（1.3%）。分割記録を持つ銘柄のアノマリー492件のうち470件は記録と別の日 = **記録がある分割は既に正しく調整済み** |
| 「きれいな分割比」を主判定にする | **しない** | `ATLX` 1.50→0.75、`MRDN` 1.80→3.60 のように**ぴったり 0.500 / 2.000 になるのは低位株のティック振動**。むしろ誤検出源 |
| 補正テーブルによる価格修正（旧案②の本体） | **本計画では扱わない** | 対象が確定してから判断する。本物の分割はごく少数と分かったため、規模が当初想定と全く違う |
| 母集団からの除外（旧案③） | **本計画では扱わない** | 同上。ノイズ除去後に残った件数を見てから判断する |

## 3. 変更内容

### 3.1 判定ロジックの共通化（新規: `backend/indicators/price_anomaly.py`）

**なぜ**: 現状 `weekly_maintenance.py` に閾値が直書きされ、

```python
def classify_price_jump(row, context) -> str:
    """段差を分類する。

    Returns:
        "virtual"      … 仮想テーマ指数。構成銘柄の入れ替え、または構成銘柄の分割の継承
        "market_wide"  … 同日に多数の銘柄が同時に動いた。市場イベント
        "low_price"    … 低位株のティック振動
        "split_suspect"… 未調整の分割の疑い（極端な比率＋売買代金の連続）

    """
```

### 3.2 除外ルール（実測に基づく）

| ルール | 根拠 | 除外数（実測） |
| :--- | :--- | ---: |
| ティッカーが `_..._` | 仮想テーマ指数。テーマ自体は分割しない（**ただし構成銘柄の分割は継承するので、構成銘柄側を直したら再合成が要る**） | 43件 |

| ジャンプ直前の株価が閾値未満 | 低位株のティック振動。`ATLX` は $0.75〜$1.50 帯 | 要調整 |
| ジャンプ直前の平均売買代金が閾値未満 | 実売買しない銘柄。実測で >$5 かつ >$1M/日 に絞ると 1,034 → 468件 | 566件 |

## 7. 途中発生した課題

### テストが設計の穴を2つ突いた（実装前に書いた効果）

実装直後に2件失敗し、どちらも**設計の誤り**だった。

1. **併合を取り逃す**: `WBX`（1:20 併合）は併合**前**が $1 の低位株なので、
   前日終値で足切りすると本物の併合が `low_liquidity` に落ちる。
   → 価格の下限は**段差の前後で高い方**で見るよう修正。
2. **判定不能を断定していた**: `CORZZ`（出来高0）は比率が中庸帯だったため
   売買代金の判定に到達せず `real_move` になっていた。
   → 出来高が取れない時点で比率に関わらず `undecided` にするよう修正。

どちらも**実測ケースをテストに書いていたから見つかった**。作り物のデータでは出なかった。

### 週次メンテの N+1 クエリも解消した

旧実装は銘柄ごとに価格を取得するループだった（3,000銘柄分のクエリ）。
分類に売買代金が必要になったため書き直す必要があり、ついでに1本のクエリにまとめた。
