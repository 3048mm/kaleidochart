## 1. 背景と目的

現行 E1/E2（VCP）は**状態スクリーン**で、収縮した保ち合い（trend_template + 低 vcr + 高値至近）が成立している**間ずっと毎日発火**する。このため:
- 1つのセットアップが再エントリー水増しの温床になる（2026-07-05 実測: E1 は 608→40件＝約93%が同一土台の重複）。
- 測っているのは「土台の初日のエッジ」で、VCP の本来のトレード対象（ブレイク）とズレる。
- 加えて 52週高値フィルタが実は無効（no-op）で長期間気付かれなかった（2026-07-05 修正済み）。数値の信頼性が低い。

**方針: E ファミリーを丸ごと「ブレイクアウトイベント」の期間別バリアントに作り直す。** 状態版 E1/E2 は残さず置き換える。「昨日まで収縮した高値圏の土台にあった銘柄が、今日ピボットを出来高膨張で終値上抜けた日」だけを発火させ、ブレイクの**基準となる高値ウィンドウ（＝期間）**でバリアントを分ける。ブレイクは1セットアップにつき1回なので再エントリー退化を構造的に解消し、各シグナルが独立になり LCB が正直になる。実際の VCP トレード（ブレイクを買う）とも一致する。

**成功条件**: 期間の異なる VCP ブレイクスクリーンが学習2期間＋ホールドアウトで評価でき、旧状態版よりシグナルが疎・独立で、LCB が信頼できる状態になる。

## 2. スコープと設計判断

### 2.1 変更すること
- 汎用の特殊フィルタ `is_vcp_breakout`（ピボットの高値ウィンドウをパラメータ化）を追加。
- E1/E2 を**状態版からブレイク版へ作り直す**（同じ E1/E2 名を再利用。旧 study は E1_old/E2_old 等でユーザーが退避）。
- ブレイク版のバリアントを高値ウィンドウで差別化（§3.2）。

### 2.2 変更しないこと / 確定した設計判断

| 論点 | 判断 |
|---|---|
| 実装方式 | **特殊フィルタ**（screener_filters.py の純関数）＋ prev マージ。RRG の `rrg_leading_in` と同じクロス日パターン |
| 状態版 E1/E2 | **廃止**（ブレイク版へ置き換え。併存させない） |
| 63日/52週ウィンドウ | 既存カラム `dist_63d_high_pct` / `dist_52w_high_pct` で計算可 → **T3 変更なし・サンドボックス不要** |
| 21日（短期）ウィンドウ | 該当カラムが無く新規 T3 カラム `dist_21d_high_pct` が要る → **T3 変更・サンドボックス発生**。採否は §4-Q1 |
| 再エントリー | デフォルト（1銘柄1ポジション）のまま。イベント化で発火が疎になりブロックはほぼ不発（＝根治側で解決） |

## 3. 変更内容

### 3.1 特殊フィルタ `filter_vcp_breakout`（indicators/screener_filters.py）
RRG フィルタと同じ「prev + 当日」パターン。パラメータ `high_window`（63 か 252）で参照カラムを切り替える。条件（v1 案）:
- **前日まで収縮した高値圏の土台**: `prev_vcr <= vcr_contraction_max`（例 0.8）AND `prev_dist_52w_high_pct >= -base_high_tol`（例 -15%）
- **当日ブレイク（ピボット上抜け）**: `prev_dist_{W}_high_pct < -pivot_gap`（昨日は基準高値の下）AND `dist_{W}_high_pct >= -pivot_tol`（今日は基準高値に到達/更新）。`{W}` = high_window
- **出来高膨張**: `vol_surge_21 >= breakout_vol_mult`（例 1.5）＝収縮の逆
- **上昇トレンド地合い**: `is_trend_template == 1`
- prev カラム欠損時は全通過フォールバック（既存特殊フィルタと同挙動）

### 3.2 E ファミリーのバリアント（backtest_config.toml）
高値ウィンドウ＝期間で差別化。**サンドボックス不要の 2 本を確定案**とし、短期版は §4-Q1 の判断次第:

| 名称 | ピボット | 位置づけ | カラム |
|---|---|---|---|
| **E1_vcp_breakout_mid** | 63日高値（≈3ヶ月ベース） | 中期 VCP・標準 | 既存 |
| **E2_vcp_breakout_52w** | 52週高値（新高値ブレイク） | 長期・最高確度・最も稀 | 既存 |
| （E3_vcp_breakout_short） | 21日高値（≈1ヶ月ベース） | 短期・早期・多発火 | **要新規カラム** |

各バリアントは `min_avg_hits_per_day` を低め（例 0.02）に設定（イベント系は疎）。`max_allowed_dd = 20`（VCP 低ボラ設計）。

### 3.3 prev マージ対象カラムの追加（backtest_screener.py）
現状 prev マージは `rs_ratio_e21, rs_momentum_e21, rs_macd_hist_21`。ここに **`vcr, dist_63d_high_pct, dist_52w_high_pct`**（短期版採用時は `dist_21d_high_pct` も）を追加。`is_vcp_breakout` を needs トリガーに登録。

### 3.4 SPECIAL_FILTER_KEYS 登録 + ディスパッチ
D-2 共通レジストリに `is_vcp_breakout` を追加し、API（screener_cross_section）とバックテスト双方で同一関数を使用。

| | 総シグナル | 1銘柄あたり平均発火 | 最大 | 1日平均 |
|---|---|---|---|---|
| E1_state（旧状態版） | 162 | **3.12回** | 10回 | 0.645 |
| E1_vcp_breakout_mid（新・63日） | 59 | **1.04回** | 2回 | 0.235 |

### 検出数の再設計（初回は過少 → change_1d ベースへ）

初回設計（ピボット距離クロス）は 2024-06〜2025-05 で 54〜59件と過少で、学習2期間でも60-70件しか出ず LCB の信頼区間が広すぎた。ファネル診断で `dist_Nd_high_pct` の構造的欠陥を特定し、ブレイク検出を `change_1d_pct` の大陽線に再設計（§7 参照）:

| 設計 | 1年(251日)の検出 | 備考 |
|---|---|---|
| ピボット距離クロス（旧） | 59件（0.24/日） | dist の当日含みで新高値日が落ちる |
| pivot_gap/tol 緩和 | 59件 | 改善せず＝指標が不適と判明 |
| **change_1d ベース（新）** | **113件（0.45/日）** | 勝率50.4%・PF1.37・期待値+1.06%・α+0.08% |

学習2期間（約650営業日）換算で約290件相当となり、LCB 評価に十分なサンプル数を確保。

## 7. 途中発生した課題
- **52週版のピボット列名の整理**: 当初 filter を `prev_dist_252_high_pct` 参照で書いたが、実際の prev マージ命名は `prev_dist_52w_high_pct`。252=52週は base チェックと同一列なので `prev_dist_52w_high_pct` に統一（プライベート列を作らない）。
- **config 検証の誤警告**: `is_vcp_breakout` に随伴する数値パラメータ（breakout_vol_mult 等）が `min_/max_/is_` 接頭辞を持たず「invalid parameter」警告を出した。`rrg_intensity_threshold` と同様に `FILTER_ATTACHED_PARAM_KEYS` ホワイトリストを新設して解消。
- **deny-by-default の設計判断**: 他の prev 依存フィルタは prev 欠損時 no-op（全通過）だが、ブレイクは前日比較が本質のため全 False に倒した（全通過だと「全銘柄がブレイク」の危険な過剰包含になる）。テストで固定。
- **検出数が過少（初回最適化で60-70件）→ ブレイク検出方式を change_1d ベースに再設計（2026-07-05）**: ファネル診断で「今日ピボット到達≥-0.5%」が生存率3.4%の主犯と判明。原因は `dist_Nd_high_pct`＝「終値−高値ローリング最大（当日含む）」の構造的欠陥で、当日ザラ場で新高値を付ける強いブレイク日ほど終値が(新)高値から乖離して落ちる（収縮＋高値圏の翌日 dist は95%点でも-2.34%）。**pivot_gap/pivot_tol の緩和（0.5/1.0→1.5/3.0）では改善せず**（59件のまま）、指標自体が不適と判断。ブレイク検出を **change_1d_pct の大陽線**に切り替え、dist は緩い「高値近傍」ゲート（near_high_tol、既定4%）に降格。パラメータを `pivot_gap/pivot_tol` → `near_high_tol/breakout_change` に置換。診断ファネルで **119件/251日≈0.47件/日**（学習2期間で約300件相当）に改善。API の cross-section に `change_1d_pct` を追加。
