## 2. スコープと設計判断

### 2.1 変更すること

参照記事の原則「ハーネスの各要素は、モデルが何をできないかについての仮定をエンコードしている。
モデル性能の向上に伴い、不要になった部分を段階的に削除する」に従い、
**記述の削除可否を次の基準で判定する**:

| 判定 | 基準 | 例 |
| :--- | :--- | :--- |
| **削除する** | モデルの出力形式・思考手順に関する回避策 | ツール呼び出しの malformed 対策 |
| **残す** | 環境（OS・シェル・文字コード・Git・ファイルシステム）に起因 | CP932 / BOM、`.bat` のマルチバイト、`git worktree remove` のジャンクション追跡 |
| **残す** | このリポジトリ固有のデータ構造・運用の制約 | データ3分類、変更種別 A〜D、プロビジョニング |

**モデルが変わっても環境起因のルールは不要にならない。ここを一緒に削ると事故が戻る。**

### 2.2 変更しないこと（確定した設計判断）

| 論点 | 判断 |
| :--- | :--- |
| ワークツリーを切って作業するか | **切らない**。本項目は worktree の撤収そのものを含み、対象の中で作業すると自分の足元を消す。変更種別も D（設定・ドキュメント）と `tools/` のスクリプト1本のみ |
| `doc/agent_execution_rules.md` の肥大（581行） | **問題としない**。検索前提の資産であり、常時読み込みの CLAUDE.md とは別基準で扱う |
| CLAUDE.md 全体の圧縮 | **やらない**。193行中エージェント行動ルールは40行（21%）で、残りはプロジェクト知識。肥大は発生していないと実測で確認済み |
| skill の正本を `.agents` に戻すか | **戻さない**。`.claude` 側が新しく、孤児プロセスの節（§6）は `.agents` に存在しない。同期方向は `.claude` → `.agents` |

### 3-D. hook のトリガー記録

- **何を**: `git_guard.ps1` が deny / ask を返したときに、日時・判定・理由を追記する。
- **なぜ**: 現在ブロックしても痕跡が残らず、**ルールが実際に効いているのか空振りなのかを測れない**。
  段階的簡潔化（3-C）を今後も続けるには、どのルールが発火しているかの記録が要る。
- **対象**: `tools/hooks/git_guard.ps1`、出力先は `logs/`（`.gitignore` 済み）
- **注意**: このファイルは **ASCII のみ**（PowerShell 5.1 が BOM なしを CP932 と読むため）。
- **設計判断（2026-09-08）**:
  - **発火時だけでなく allow も記録する**。発火だけ記録すると「一度も発火していないルール」と
    「フックが動いていない」が区別できず、段階的簡潔化の削除判断に使えない（分母が要る）。
  - ただし **git を含むコマンドに限定**する。全 Bash 呼び出しを記録すると信号が埋もれる。
  - ルールは短いコード（`add-all` / `force-push` / `push-main` / `amend` / `commit-main`）で
    記録する。理由文そのものを書くと集計できない。
  - **ログ失敗は判定に影響させない**（try/catch で握り潰す）。stdout へは判定 JSON 以外を
    絶対に書かない（フックの契約を壊すため）。
  - ログは **ASCII 固定**。コマンド中の日本語は `?` になるが、目的は発火回数の集計であり、
    UTF-8 にすると `Get-Content` 側で §5.2 の誤デコードを踏む。
  - 1MB を超えたら1世代だけローテートする。
- **集計コマンド**:
  ```bash
  grep -o 'rules=[^ ]*' logs/git_guard.log | sort | uniq -c | sort -rn
  ```
  発火ゼロが続くルールは、`doc/issue_list.md` P3「効果を測る手段が無い」で挙げた
  **段階的簡潔化の削除候補**として扱う。
- **検証時の実測メモ**: テスト用コマンドに `git push --force` 等の文字列を素で書くと、
  **外側の呼び出し自体がガードにブロックされる**（正しい動作）。文字列を分割して回避した。

### 3-G. 撤収スクリプト `tools/remove_worktree.ps1`（2026-09-09 追加）

- **何を**: `git worktree remove` を直接使わせず、撤収を1本のスクリプトに集約する。
  ①作業が失われる条件で中断 → ②reparse point を全検出して**リンクだけ**外し、
  ターゲットの生存を1件ずつ確認 → ③撤収（未登録の残骸はディレクトリ削除）→
  ④マージ済みのときだけブランチ削除、の順で実行する。
- **なぜ**: 撤収作業中に、2つのワークツリーが
  `<worktree>/frontend/node_modules -> <本体>/frontend/node_modules` の
  ジャンクションを持っていることが判明した。素で `git worktree remove` していれば
  **本番作業環境の node_modules（143エントリ）が全損**していた。
  §11.3 に「ジャンクションを置くな」という規律はあったが、**守られていなかった**。
  規律で防げないものは手順で防ぐ。
- **実測（カナリアによる再現）**:

  | 経路 | カナリアのファイル数 |
  | :--- | ---: |
  | 素の `git worktree remove --force` | 2 → **0**（全削除） |
  | `tools/remove_worktree.ps1` 経由 | 1 → **1**（無傷） |

- **迂回の封じ込め（2026-09-09 追加）**: 素の `git worktree remove` は
  PreToolUse フック `git_guard.ps1` が `ask` に落とす（ルールコード `worktree-remove`）。
  `worktree add` / `worktree list` は対象外。スクリプトが内部で呼ぶ `git worktree remove` は
  子プロセスのためフックを通らず、通常どおり動くことを実測で確認済み。
- **対象**: `tools/remove_worktree.ps1`（新規）、`tools/check_worktrees.ps1`（提示コマンドの差し替え）、
  `tools/hooks/git_guard.ps1`、`doc/agent_execution_rules.md` §11.3、CLAUDE.md「Git 運用」

## 7. 途中発生した課題

1. **計画書への転記で最優先項目を落とした（2026-09-07）** — 会話で確定した14項目のうち
   反証欄（P0 の1件目）が §3 から抜けていた。元データは参照可能な状態にあり、
   失われていたのではなく**照合しなかった**だけ。追跡表を作ってたまたま気づいた。
   → 対策として §6.2「転記の完全性」をテンプレートに新設（3-F-2）。

2. **バックスラッシュがシェル経由で展開される問題を3回踏んだ（2026-09-07〜09）** —
   `\v` → 垂直タブ、`\t` → TAB、`\r` → CR、`\\` → `\`。いずれもエラーが出ない。
   さらに**制御文字の検査自体が CR を検出できていなかった**（`read_text()` の
   universal newlines が CR を改行へ変換して読むため）。
   → §4 の3回打ち切りに従いアプローチを変更（Write/Edit ツールで書く）。
   知見は `doc/agent_execution_rules.md` §1.3 として新設し、§1 の行数分岐撤廃の根拠にもした。

3. **`agent_execution_rules.md` §1.2 の本文が既に壊れていた（2026-09-07 発見）** —
   `newline="\n"` の `\n` が実際の改行に展開され、2行に割れていた。
   **§1.1 が警告しているサイレント破壊が、その §1.1 を含む文書の中で起きていた。**
   → 修正し、経緯を NOTE として残した。

4. **worktree 撤収の直前にジャンクションを発見、事故を回避（2026-09-09）** 🔴 —
   `rs-dot-age` と `dataview-columns` が本体の `frontend/node_modules`（143エントリ）を
   指すジャンクションを持っていた。素で `git worktree remove` していれば**本体側が全損**していた。
   カナリアで再現も確認（素の経路 2→0、スクリプト経由 1→1）。
   → 規律ではなく手順で防ぐため `tools/remove_worktree.ps1`（3-G）を新設し、
   素の `git worktree remove` は `git_guard.ps1` が `ask` に落とすようにした。

5. **`README` がミラーの drift として誤検出された（2026-09-07）** —
   `.agents/skills/README.md` は正本側に対応物を持たないため、初回実行で必ず exit 1 になる状態だった。
   → `MIRROR_ONLY` で除外し、孤児検出は従来どおり効くことを回帰確認した。
