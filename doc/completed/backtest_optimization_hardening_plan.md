## 0. レビューで確定した設計判断（変更しないもの）

| 論点 | 判断 |
|---|---|
| 当日終値エントリー | 24時間取引可能な証券会社での「引け後データ更新→オーバーナイト発注」運用と整合するため**運用モデルとして許容**。ただし next_open との感度比較を可能にする（→修正1） |
| 終値ベースのストップ評価 | 実運用が「-8%割れ確認→引け成行」なので**設計通り**。ギャップダウンは実際の終値（例: -40%）で記録されることをコード確認済み |
| 定額手数料・税金 | 全パラメータ候補の期待値を一律に下げるだけで argmax を変えないため**型1では導入しない**（型3シナリオテストで導入済み・現在0%設定） |
| 期間ごとの最低活動量ゲート | **意図された設計**。「ベアは事後にしか分からない」ため、スクリーナ自体はレジーム非依存に安定して機能すべき（ベアでも勝率が安定するスクリーンを選抜したい）。レジーム認識とポジションサイズ調整は型3（MTS 参照）の責務という役割分担 |
| ATR連動指値の約定モデル | 型3シナリオテストの改善として issue_list P2 に記録済み（2026-07-05） |

## 1. 修正項目（6件）

### 修正1: エントリーモード切替（close / next_open）
- `[general] entry_mode = "close"`（デフォルト、現行互換）/ `"next_open"` を追加。
- next_open: シグナル翌営業日の**寄付価格**をエントリー価格にする。exit 評価は従来同様シグナル日より後の終値から
  （翌日終値が最初の評価点 — 寄付エントリー当日の終値でストップ判定される）。翌営業日の価格が無い銘柄はシグナル破棄。
- 目的: 「引け値で買えること自体がエッジ」なのかの感度計測。選抜は保守側（next_open）、実運用期待値は close 側で見る使い分けを可能に。

### 修正2: ドル建て売買代金の固定下限（ハード制約）
- `[general] min_avg_dollar_volume_21`（デフォルト 2e6 = $2M/日）。**最適化対象外**の全戦略共通フィルタ。
- `preload_data` で `close × volume` の21日平均を df_prices に列として付与し、シグナルスキャン時に足切り。
- 根拠: 1ポジションが日次売買代金の1%以下なら市場実勢を壊さず約定できる経験則。Optuna が「約定不能な非流動の隅」を発見するのを構造的に防ぐ。
- 将来: T3 に売買代金カラムを正式追加してライブスクリーナーとパリティを取る（P1 追加インジケータ作業と合流）。

### 修正3: 目的関数を期待値の下側信頼限界（LCB）へ
- `LCB = expectancy − 2 × SE`、`SE = std(トレードpnl) / √n`（k=2、片側約97.7%）。
- `calculate_metrics` に `pnl_std` / `expectancy_se` / `expectancy_lcb` を追加し、
  `calculate_custom_score` の主指標を expectancy → expectancy_lcb に差し替え。ペナルティ構造は維持。
- 効果: 少数トレードのまぐれ（5件×+8%等）が SE 増大で自動的に沈む。ベア期間でも件数を伴って安定して勝つ
  パラメータほど高スコア（§0 の設計思想と整合）。
- **旧 study とはスコア非互換**。ユーザーが既存 study を `_old` にリネームしてから再学習する運用。

### 修正4: 同一銘柄の再エントリー禁止（デフォルト・TOML オプションなし）
- 建玉が生きている間（entry_date < signal.date <= exit_date）の新規シグナルはスキップ。exit 翌営業日から再エントリー可。
- 背景: 急騰継続銘柄が毎日シグナルを出し「1つの上昇ムーブ=5〜10トレード」に水増しされ、
  トレード間の独立性が壊れて統計全般が歪む。**特に VCP（E系）が評価不能になっていた課題**。
- `run_single_strategy` に内部引数 `allow_reentry_during_hold=False` を持つ（TOML には出さない。修正前後比較レポート専用）。

### 修正5: ドローダウンの mark-to-market 化
- 確定損益累積（exit日ソート）→ **日次エクイティカーブ**からの DD 計算に変更。
- 各トレードの entry〜exit 間を日次終値で評価。部分利確後は確定分（1/3）を固定し残り 2/3 のみ時価評価。
- 正規化は現行と同じ Little's Law（avg_slots 割り）を維持。旧 additive 版は `max_drawdown_legacy_pct` として併記。
- 効果: failsafe 長期保有中の含み損の谷・シグナル集中期の同時被弾が DD に現れ、`max_allowed_dd` ゲートが実効化。

### 修正6: ホールドアウト自動評価（型1内の validation）
- 学習期間（現行のまま: Bear 2022 + Bull 2024-06〜2025-12）とは別に、**スコア計算に一切使わない検証セット**を定義:

| セット | 期間（窓） | 検証する性質 |
|---|---|---|
| stress_bear | 2018-10-01〜2018-12-31, 2020-02-01〜2020-05-31 | 引き締め型ベアへの汎化 + 事故型クラッシュのテール耐性。**勝率の安定性**が設計目標なので明示レポート |
| calm_recent | 2023-01-01〜2023-12-31, 2026-01-01〜2026-06-30 | レンジ相場での無駄撃ち + 学習期間より後の疑似フォワード |

- 注意: 2025-02〜04 は学習期間 Bull 2024-25 に内包されるため**検証に使用禁止**。2021 は未使用のまま温存（将来のブル側検証候補）。
- study 完了後に best-N trial（N=5）を各セットで評価。**セット内の全窓のトレードをプールしてから指標計算**
  （3ヶ月窓単体に活動量ゲートを当てると静かなスクリーンが不当に沈むため）。窓別内訳も併記。
- 出力: コンソール表 + `backtest_results/holdout_{strategy}.json`。in-sample スコアとの並記で劣化率を見る。

## 4. 修正前後比較の主な所見（詳細: backtest_framework_comparison.md）

学習2期間（Bear 2022 / Bull 2024-25）で全戦略の TOML 記載パラメータを新旧モードで実行:

1. **再エントリー水増しの規模**: モメンタム系はトレード数が約40〜55%減。**VCP 系は E1: 608→40件、
   E2: 420→18件（約95%減）** — タイトな保ち合いが毎日同一シグナルを出し続けていたため。
   旧フレームワークの VCP 評価数値は実質無意味だったことが定量的に確認された。
2. **MTM DD の可視化効果**: 旧 additive DD では見えなかった谷が出現。Bear 2022 の
   A_momentum_breakout はポートフォリオ等価 DD -102%（事実上の破綻）、B3 は -115%。
   `max_allowed_dd` ゲートがようやく実効化した。
3. **next_open 感度（執行依存度）**: Bull 期の期待値は close 比で約 -0.3〜-2.3pt 低下するが、
   主要戦略のエッジは正のまま残存（例: B2 +7.4→+5.8、B3 +8.0→+5.7）。
   「引け値で買えること」への依存は一部あるがエッジの主因ではない。
4. **LCB の判定**: Bull 期でも LCB がプラスを維持するのは A/B2/B3/B5 系（+3.6〜+4.0）。
   C2 は期待値 +0.29 に対し LCB -1.75 で「統計的にゼロと区別できない」ことが明示された。
