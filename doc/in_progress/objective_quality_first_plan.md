## 1. 背景と目的

### 1.1 現行の目的関数

```
score = period_CAGR / dd_penalty × detect_adequacy(hits/day) × lcb_gate
```

`period_CAGR` を主軸に、検出件数を `detect_adequacy` で**掛け算**して実用帯へ寄せている
（`backend/optimization_runner.py::calculate_custom_score`）。

### 1.2 何が問題か（実測）

単独戦略13 × パラメータ2世代 = 26観測で、**型3（個別銘柄シナリオ・有限資産8枠）の CAGR**
との順位相関を取った:

| 説明変数 | Spearman |
| :--- | ---: |
| **1取引%（質）** | **+0.951** |
| 質 × 量 | +0.866 |
| 枠稼働率 | -0.372 |
| 取引数（量） | -0.210 |
| 最大DD（型1） | +0.151 |
| **現行の最適化スコア** | **+0.665** |

**質はほぼ完全に実運用 CAGR を説明する（+0.951）のに、現行スコアの説明力は +0.665 に留まる。**
`period_CAGR` は質と量を混ぜた指標であり、**量を稼ぐ経路でも点が入る**ことが原因と考えられる。

取引数の帯別に見ると、多いほど CAGR が低い（下表）。ただしこれは因果ではなく、
**取引を増やせるのは条件が緩い＝質が低い戦略だから**である（量は質の代理変数として負に働く）。

| 取引数帯 | 件数 | 平均CAGR | 平均1取引% | 平均稼働率 |
| ---: | ---: | ---: | ---: | ---: |
| 0-100 | 4 | 2.15 | 1.88 | 23.1% |
| 100-200 | 5 | **13.73** | 5.63 | 36.2% |
| 200-300 | 9 | 13.36 | 3.98 | 62.3% |
| 300-450 | 7 | 6.33 | 2.49 | 83.4% |
| 450- | 1 | -2.16 | 0.26 | 90.3% |

**本当に取引数が足りないのは 0-100 の帯だけ**（CAGR 2.15・稼働率23%）。
つまり検出件数は**最適化すべき対象ではなく、満たすべき下限**である。

### 1.3 組み合わせ運用という前提の変化（2026-08-22 検証済み）

`B256_union`（B2+B5+B6 の和集合）をフル実行した結果:

| | CAGR | DD | Calmar | 取引 | 1取引% |
| :--- | ---: | ---: | ---: | ---: | ---: |
| B2 単独 | 13.93 | 18.0 | 0.77 | 125 | 6.89 |
| B5 単独 | 21.47 | 28.1 | 0.76 | 175 | 7.41 |
| B6 単独 | 15.71 | 25.9 | 0.61 | 228 | 5.05 |
| **B2+B5+B6** | **30.41** | 29.8 | **1.02** | **313** | 6.38 |

5モデル中4モデルで単独ベストを上回った。さらに **3戦略が一致した銘柄（score=3, 415件）は
1取引 13.87%** と、単独最高の B5（7.41%）の約2倍。

**枠を埋めるのは組み合わせの仕事であり、個々の戦略の仕事ではない。**
個々の戦略に求めるのは「質が高いこと」と「最低限の検出があること」の2つでよい。

### 1.4 目的

型1の目的関数を **「質を最大化し、検出件数はゲートで担保する」** 形へ変える。
**成功条件: 新スコアと型3 CAGR の順位相関が、現行の +0.665 を明確に上回ること。**

## 2. スコープと設計判断

### 2.1 変更すること

- `calculate_custom_score()` を質主軸へ再設計し、検出件数を**掛け算からゲートへ**変更
- 型1の税を 0.0 に戻す（型3は 0.2 のまま）ための**経路分離**
- `avg_holding_days` 等を `trial_user_attributes` に保存し、**将来の再スコアリングを可能にする**

### 2.2 変更しないこと（確定した設計判断）

| 論点 | 判断 | 理由 |
| :--- | :--- | :--- |
| 型3（シナリオテスト）の評価軸 | **CAGR と DD のまま** | 最終評価は実運用の資産成長とドローダウン。ここは変えない。変えるのは**型1が何を目指すか**だけ |
| 型3の税 | **0.2 のまま維持** | 実運用シミュレーションに税は必須。2026-08-19〜20 に配線を修正したばかり |
| `detect_adequacy` の連続関数そのもの | **関数は残すがスコアには掛けない** | `fast_prune` の足切り判定には引き続き使える。削除すると速度ガードが壊れる |
| 型1に固定枠・コストを導入する | **やらない** | 型1は無限資金・レジーム非依存が**意図**（仕様書 §6.1）。枠の制約を型1に持ち込むと型3との役割分担が壊れる。**枠は組み合わせで埋める**というのが本計画の立場 |
| 組み合わせ（和集合）を型1で最適化する | **やらない（将来課題）** | 組み合わせ最適化は探索空間が戦略数の積になる。まず個々の質を上げ、組み合わせは型3で検証する |

### 2.3 §6.1 の検証を経て確定した設計判断（2026-08-22）

**先に方法論の訂正**: 当初「質は型3 CAGR を +0.951 で説明する」と記載していたが、
これは**型3の1取引% と型3の CAGR** という同一シミュレーション内部の相関であり、
**型1の指標が型3を予測できるか**の検証になっていなかった。正しく測ると +0.749。

#### 型1 → 型3 CAGR の予測力（26観測・ブートストラップ95%CI）

| 候補 | 相関 | 95%CI |
| :--- | ---: | :--- |
| （参考）型1 CAGR 単体 | **+0.824** | [+0.609, +0.930] |
| A: 質のみ（`avg_gain`） | +0.749 | [+0.486, +0.881] |
| D: `lcb` / DDペナルティ | +0.746 | [+0.495, +0.863] |
| **現行スコア（基準）** | **+0.649** | [+0.295, +0.902] |
| C: `expectancy_lcb` のみ | +0.627 | [+0.259, +0.828] |
| **B: 質 / DDペナルティ** | **-0.504** | [-0.791, -0.076] |

**上位4つの信頼区間は大きく重なり、差は統計的に有意ではない。** 26観測ではこの程度の差を
区別できない。**したがって「相関が最も高いから」を採用理由にしてはならない。**

一方で明確に言えることが2つある:

1. **現行スコアは素の型1 CAGR より予測が悪い**（+0.649 vs +0.824）。
   `dd_penalty` × `detect_adequacy` × `lcb_gate` の3つの加工が、合わせて予測力を落としている。
2. **現行の DD ペナルティは有害**。候補 B は符号が反転し、信頼区間も 0 を跨がない
   （唯一の明確な悪材料）。

#### 確定した判断

| # | 論点 | 判断（ユーザー 2026-08-22） | 根拠 |
| :--- | :--- | :--- | :--- |
| **Q1** | 質の指標 | **質を主軸にする**（`avg_gain`） | 相関では型1 CAGR と有意差なし。採用理由は**設計思想**——「枠を埋めるのは組み合わせの仕事、個々の戦略は質を担う」（§1.3）。相関を根拠にしない |
| **Q2** | DD ペナルティ | **緩和して残す**（撤廃しない） | 数値上は型1 DD が型3 CAGR と **+0.770** と正相関し、罰すると良い戦略を落とす。しかし**大きすぎる DD は運用を継続できなくする**（ユーザー判断）。現行の「`max_allowed_dd=35` 超過分を2乗」は過剰なので、**常識外れの DD だけを弾く安全弁**へ後退させる |
| **Q3** | 検出件数ゲートの下限 | **0.3 件/日** | 現行の `min_avg_hits_per_day = 1.0` をハードゲート化すると **26観測中15件が失格**し、B1/B2/B3/B5/B6 という上位戦略がほぼ全滅する（B5 は 0.51件/日、B2 は 0.78件/日）。現行のハード足切り `prune_floor = 0.2` に近い 0.3 が妥当で、E1・E2 のみを落とす水準 |

#### 「質が上がれば DD も改善するのでは」への検証結果（Q2 の補足）

ユーザーの問いに対し実測した結果、**部分的にしか成り立たない**:

- **横断**: 型3 1取引% vs 型3 DD の相関は **+0.065（ほぼ無相関）**。
  DD が最小の帯は質が最低クラスの帯（1-3%・DD 12.4）で、これは取引が少なく枠が空いている E1/E2。
- **対応のある変化**: 質が上がった4戦略のうち**3つで DD も低下**（B2 は 25.6 → 18.0 と -7.6pt）。
  ただし全体の相関は -0.103 と弱い。

**結論**: 傾向はあるが保証ではない。DD は質ではなく「どれだけ張るか」で決まる部分が大きい。
よって DD ペナルティを完全に外すのは危険で、**緩和して残す**という判断が妥当。

### 2.4 DD ペナルティの具体形（2026-08-22 確定）

#### 経緯

ユーザーの指摘: **DD 50% なら CAGR 100% ないと1年で取り戻せない**。
DD は線形のコストではなく、回復に必要なリターンは `1/(1-DD)-1` で凸に効く。

| DD | 回復に必要なリターン |
| ---: | ---: |
| 20% | 25.0% |
| **24.5%（SPY 2022-2026 実測）** | **32.5%** |
| 35% | 53.8% |
| 50% | 100.0% |
| 80% | 400.0% |

現行の「`max_allowed_dd=35` 超過分を2乗して1.5倍」は、DD 60%（超過25）で係数が3桁になり、
**回復コストの実態を大きく超える事実上のハードカット**として働いていた。
これが §2.3 の候補 B が符号反転（-0.504）した正体。

#### `max_allowed_dd = 35` の根拠と、その問題

ユーザーの設定根拠は **SPY ETF バックテストの DD 33%**（「SPY より深い DD はペナルティ」）。
考え方は妥当だが、**適用先のスケールが合っていなかった**:

1. **33.7% は全履歴（コロナ暴落を含む）の値**。最適化が実際に評価する学習期間の SPY DD は
   **2022通年 24.5% / 2024-06〜2025-12 18.8%**。
2. **型1 の DD は型3 の約2倍**（中央値1.93倍・範囲0.76〜3.39）。
   型1 は無限資金・`avg_slots` 正規化の値であり、実際に体験する DD ではない。
   よって閾値 35 は**型3 換算で約18%** に相当し、SPY（24.5%）**より厳しい**基準になっていた（意図と逆）。

#### 型1 DD のスケール差の正体（実測で判明）

型1 は `max_dd ÷ avg_slots`（Little の法則 = 到着率 × 平均保有日数）で正規化するため、
**戦略ごとに正規化先の枠数が違う**。型3 は常に8枠固定。

| 戦略 | avg_slots | 型1/型3 の比 |
| :--- | ---: | ---: |
| E2 | 2.30 | 1.93 |
| **B5** | **8.26** | **3.39** |
| B2 | 15.16 | 2.11 |
| **G1** | **92.14** | **0.94** |

**比と avg_slots の相関 -0.698。** 枠が少ないほど集中度が高く型1 DD が膨らむ。
このため素の型1 DD は型3 DD を **+0.533** としか予測できず、
**B5（型1で最悪95.1 → 型3では8位28.1）と G1（型1で9位40.4 → 型3で最悪42.8）が逆転**していた。

#### 確定した形

```
dd_est = 型1DD × √avg_slots / 9.1     # 型3 相当の DD を推定
score  = 質 × (1 - dd_est/100)         # 回復コスト 1/(1-DD) の逆数
```

| 変換 | 型3 DD との順位相関 | 平均絶対誤差 |
| :--- | ---: | ---: |
| 素の型1 DD | +0.533 | — |
| 固定係数 1.93 | +0.533 | 8.6pt |
| **√avg_slots 補正** | **+0.896** | **3.9pt** |

- 閾値も2乗も使わない。**回復コストという経済的実態がそのまま係数になる**
- `avg_slots` は型1 内部で既に計算済み（`backtest_report.py:174`）。そのまま使える

> **注意（過適合の懸念）**: 係数 **9.1 は13点から当てはめた経験値であり理論値ではない**。
> **順位（+0.896）は信頼できるが、絶対値は 3.9pt 程度の誤差を含む。**
> 係数がずれても順位は保たれるため最適化の挙動への影響は限定的だが、
> **再最適化後の型3 結果で係数を再検証する**（§6.3）。

## 3. 変更内容

### 3.1 目的関数の再設計（`backend/optimization_runner.py::calculate_custom_score`）

```
【現行】 score = period_CAGR / dd_penalty × detect_adequacy(hits/day) × lcb_gate
【新案】 検出件数が [lo, hi] の外  → 失格（大きな負値）
        検出件数が [lo, hi] の内  → score = quality / dd_penalty
```

- **検出件数は掛け算ではなくゲート**。帯の中にいる限り、取引数はスコアに影響しない。
  これにより「量を増やして点を稼ぐ」経路が消える
- `quality` は §4 の判断で `avg_gain` または `expectancy_lcb`
- `lcb_gate`（現行の 0.5 倍割引）は、`expectancy_lcb` を主指標にする場合は**不要になる**
  （二重に効くため）。`avg_gain` を主指標にする場合は残す

> **CAGR を完全に捨てるわけではない**。型3の評価軸は CAGR と DD のままであり、
> 型1は「型3で CAGR を最大化するために、個々のスクリーンが持つべき性質」を測る役に変わる。

### 3.2 税の経路分離

`[general] consider_tax` が全経路に効く現状を改め、**型1だけ別値を取れるようにする**。

```toml
[general]
consider_tax = 0.2              # 型2・型3（実運用シミュレーション）で使う税率
consider_tax_optimization = 0.0 # 型1（最適化バックテスト）。既定は 0.0
```

- `common_constraints.load_tax_rate()` に `for_optimization: bool = False` を追加し、
  真なら `consider_tax_optimization` を、無ければ 0.0 を返す
- `optimization_runner` / `backtest_runner`（型1経路）が `for_optimization=True` で読む
- **単位検証（`> 1.0` で `InvalidTaxRateError`）は両方に効かせる**

> **なぜ税を型1から外すのか**: 2026-08-22 の実測で、税込み最適化はパラメータが変わった
> 10戦略のうち**8戦略で型3の Calmar を悪化**させた。質は上がっていた（型1で改善5戦略、
> うち4戦略は型3でも再現）が、**取引数の減少が上回った**。質を目的関数が直接見るように
> なれば、税という間接的な手段で質を上げる必要がなくなる。

### 3.3 trial 属性の拡充

`trial_user_attributes` に以下を追加保存する（現在は保存されていない）:

- `avg_holding_days` — **単位時間あたりの質**（1取引% ÷ 保有日数）を将来評価するため。
  枠が有限な型3では、同じ +6% でも15日保有と60日保有では資本回転が4倍違う
- `avg_hits_per_day` — ゲート判定の再現に必要
- `avg_slots` — 無限資金の正規化に使われている値。型3との対応を追うため

> **今回の再スコアリングでは `avg_holding_days` が既存 trial に無いため、
> 時間正規化した質の検証はできない。** 次回の最適化以降に可能になる。

`backend_specification.md` §6.5.1（設計判断）と §6.9（Optuna）を更新する。

## 6. 検証プラン / 結果

### 6.1 オフライン再スコアリング（実装前に必ず実施）

**既存の16戦略 × 200トライアル = 3,200件を、新目的関数の候補で再スコアリングする。**
`trial_user_attributes` に `avg_gain` / `total_trades` / `max_drawdown` / `port_cagr` /
`expectancy_lcb` が保存済みなので、**再実行なしで評価できる**。

候補（それぞれ型3 CAGR との Spearman を測る）:

| 候補 | 式 |
| :--- | :--- |
| 現行（基準） | `period_CAGR / dd_penalty × detect_adequacy × lcb_gate` = **+0.665** |
| A | `avg_gain`（質のみ・ゲートあり） |
| B | `avg_gain / dd_penalty`（質 ÷ DD ペナルティ） |
| C | `expectancy_lcb`（下側信頼限界のみ） |
| D | `expectancy_lcb / dd_penalty` |

- 相関の相手は**型3 CAGR**（`output/scenario/` と `output/scenario_tax_preopt/` の26観測）
- **合わせて「型1 DD が型3 DD を予測するか」も測る**（Q2 の判断材料）
- ゲート下限を 0.5 / 1.0 / 2.0 と振って感度を見る（Q3 の判断材料）

> **注意**: 観測は26件と少ない。相関の差が小さい場合は「有意差なし」と判断し、
