- [ ] 🟡 **エージェント実行中の「見返し」がワークフローに無い — 二次検証の段の新設（2026-09-07 起票）**
  - **背景**: ハーネス／ループ観点の棚卸し（診断カルテ: https://claude.ai/code/artifact/334d29c0-f8db-49cd-ac7f-c6d31c281e61 ）で、
    **一次の成果物までは作るが、それを受け取って検算する二次の段だけが無い**という共通形が見つかった。
    人間のレビューゲートは merge に存在する（rules §7 が `git diff main..<branch>` の提示を義務づけ、
    main への直接マージを禁じている）が、**1タスクに1回・最後に一度しか効かない**。
  - **参照**: [ハーネス設計の原則](https://www.anthropic.com/engineering/harness-design-long-running-apps) —
    「プランナー / ジェネレータ / **評価エージェント**」の3層のうち、当プロジェクトは**評価だけが不在**。
    同記事は「エージェントが自作業を評価する際、自信を持ちながら仕事を褒める傾向がある」ため
    生成と評価を別エージェントに分離すべきとし、
    「スタンドアロン評価器を懐疑的にチューニングするのは、生成器に批判的になるよう仕向けるより遥かに容易」としている。
  - **内訳（後続計画書 `doc/in_progress/workflow_feedback_loop_plan.md` で扱う想定）**:
    - **バッチの実行サマリ JSON 化** — 明細（`price_anomalies_snapshot.json`・CSV 4本）は既にあり、
      欠けているのは実行サマリ（フェーズ別成否・処理件数・要対応件数）。
      現状 `logs/` は 58MB のプレーンテキストで、エージェントが結果を判定できない。
      **P3「戦略カルテの形骸化」への回答でもある**（自動生成部分を JSON で供給できれば手書きは所見だけになる）
    - **エージェント側レビュー段階の追加** — 変更種別 B / C に限定し、**ブランチ単位で1回** `/code-review`。
      全項目に立てるとコンテキスト再構築コストで割高（CLAUDE.md 自身が警告）。
      出力は「上位3件・重大度付き・テストで検出できない種類に限る」と縛らないと形骸化する
    - **PostToolUse ゲート** — `backend/**.py` 編集時に対応テストのみ実行。
      ただし**86 / 137 モジュールにテストが無い**ため、
      「対応テストが存在しない場合はその旨を報告する」まで含めないと沈黙する
    - **`.claude/commands/` の新設** — 着手・検収・撤収の手順固定。
      現状これらは CLAUDE.md の散文にしかなく、毎回手順が再構築されている
