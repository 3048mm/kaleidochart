  - **副次的に判明**: `scan_price_anomalies.py` の分類が分割を隠している（下記の別項）
  - **事象**: 分割・併合の検出と適用は yfinance の `splits` と SEC EDGAR で組んであるが、
    **適用結果が正しいかを独立に検証する手段が無い**。参照先が実質 yfinance 単独なので、
    上流が壊れているケースを構造的に検出できない。

  - **実際に起きたこと**: 価格履歴の充足（2017年分の追記）で接合部に段差が出た5銘柄を
    「上流が正・手元が古いスケール」と判断して `resync_price_scale.py` で上流へ合わせた。
    ところが **MNST は上流側が壊れていた**（2026-08-11 の ×2 分割を履歴へ遡及適用できて
    いなかった）。誤った価格の上に T3/T4 全期間再計算とデイリー更新まで実行してしまい、
    **ユーザーが TradingView で実測して指摘するまで気づけなかった**。

    さらに厄介なことに、**上流の値は当日中に変化した**:

    | 銘柄 | 12:00頃の上流adj | 14:44の上流adj | 動き |
    |---|---:|---:|---|
    | MNST | 27.81 | 13.90 | 分割が適用された |
    | APH  |  9.70 | 19.45 | 分割が**外れた** |

    Yahoo が直近分割を処理中で銘柄ごとに逆方向へ振れていた。
    **「上流と一致するか」を検算にしても、上流が動くので歯止めにならない。**

  - **なぜ既存の検査で拾えないか**:
    - `resync_price_scale.py` の `verify_after()` は「上流と一致するか」しか見ない。
      上流の誤りは**原理的に検出できない**
    - `scan_price_anomalies.py` は系列内の段差を見る。全期間が一律に同じ倍率でズレて
      いる場合は**段差が出ないので素通りする**（今回5銘柄とも素通りした）
    - `adjust_symbol_split.py` の接合部検算は人間が申告した `--factor` との照合であって、
      申告値そのものの正しさは検証しない

  - **今回、切り分けに実際に効いた手順**（現状どれもその場限りのスクリプトで資産化されていない）:
    1. **実価格からの逆算** — 2018年の実勢価格 ÷ その後の累積分割比。
       例: MNST は 2018年に約55.6ドル、以降 ×2(2023-03-28)・×2(2026-08-11) で 55.6/4 = 13.90
    2. **上流自身の段差で未適用分割を特定** — 遡及適用済みなら分割日に段差は出ない。
       段差が分割比と一致すれば上流が取りこぼしている
    3. **配当調整幅の定量検算** — TradingView は分割のみ調整、当プロジェクトは
       `auto_adjust=True` で配当も調整する。差が配当・分配金で説明できるかを計算する。
       RUSHA は配当から算出 ×0.8935 に対し実測 ×0.8936（一致率 1.0002）で正常と確定、
       VISN は 2026年の特別分配 $10.00(04-28) と $5.00(08-28) から
       0.488 × 0.570 = 0.2782 が実測比 0.278 と厳密に一致して正常と確定できた

  - **対応案（要議論）**:
    - ~~独立ソースの追加~~ → **2026-09-11 moomoo で実装済み**（上記参照）。
      「分割調整のみ / 配当調整あり」の懸念は、moomooの `get_rehab()` が分割・配当を
      別フィールドで返すため生じない（`.claude/skills/moomoo-api/SKILL.md` §5参照）
    - **無配当銘柄の調整幅チェック** — 配当が無いのに調整比が分割比と一致する場合は
      上流の取りこぼしを疑う（MNST はこれで機械的に検出できたはずのケース）
    - **上流の安定性チェック** — 書き込み直前に時間を空けて2回取得し、値が動いていたら
      中断する（`upstream-data-diagnosis` §2 の決定論テストの自動化）
    - **`resync_price_scale.py` に独立ソース照合を必須化**するか、少なくとも
      「上流一致は歯止めにならない」旨の警告を出す

  - **暫定の運用**: `resync_price_scale.py` / `adjust_symbol_split.py` を使う前に、
    対象銘柄を **TradingView など独立ソースで必ず実測確認する**。
    特に**無配当銘柄で調整比が 2.0 / 0.5 などの分割比に一致する場合は上流を疑う**。
