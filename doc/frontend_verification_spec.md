# フロントエンド検証仕様書 (Frontend Verification Spec)

## 1. 目的
本ドキュメントは、フロントエンドアプリケーションにおける表示データの正確性、UI/UX の整合性、および操作の健全性を維持するための検証項目を定義する。バックエンドから提供されるデータが、意図通りにユーザーに提示されているかを保証することを目的とする。

---

## 2. 検証方針
- **新規機能の追加**: 新規機能を追加する際は、その機能に対する単体検証項目を本検証仕様書に追記した上で検証を行う。
- **既存機能への影響**: 変更の影響範囲にある既存機能についても、改めて単体検証を実施し、デグレが発生していないことを確認する。
- **検証環境**: 検証には原則としてサンドボックス用のデータベースを用いる。
- **データの充足**: 検証内容に対してサンドボックス内のデータが不足している場合は、適宜テストデータを追加して検証を行うこと。

---

## 3. 画面別検証項目

### 3.1 ダッシュボード (`/`)
- [ ] **マーケットフェーズ**: 現在の市場フェーズ（BULL/CORRECTION等）が最新のバックエンド計算結果と一致しているか。
- [ ] **指標タブ (Indicators/Markets/Sectors/Themes)**:
    - [ ] 各リストの銘柄名、ティッカー、価格、乖離率が正しく表示されているか。
    - [ ] **色分け**: 前日比 (%) に基づき、プラスは緑、マイナスは赤で表示されているか。
    - [ ] **スパークライン**: 直近のトレンドが視覚的に正しく描画されているか。
- [ ] **ナビゲーション**: 銘柄またはテーマをクリックした際、対応するチャート画面 (`/chart/{ticker}`) へ遷移するか。

### 3.2 チャート画面 (`/chart/{ticker}`)
- [ ] **データビュー (`Data Viewer` タブ)**:
    - [ ] サンドボックス環境において、SPY および他 1 銘柄で、期待されるデータ（OHLC, インジケーター等の各項目）がバックエンドの想定通りに表示されているか。
- [ ] **基本チャート**:
    - [ ] ローソク足 (OHLC) が直近データまで表示されているか。
    - [ ] 出来高 (Volume) ヒストグラムが表示されているか。
- [ ] **テクニカル指標 (Overlays)**:
    - [ ] トグルボタンで SMA/EMA の表示/非表示が切り替わるか。
    - [ ] 移動平均線の値が、バックエンドから提供される T3 データの値と一致しているか。
- [ ] **マーカー表示**:
    - [ ] **TD9**: Sequential カウントがローソク足の上、または下に正しく配置されているか。
    - [ ] **ATR乖離**: 50日SMAからの一定以上の乖離時にマーカーが表示されるか。
- [ ] **チャート比較 (Comparison)**: 比較対象（例: QQQ）を入力し、相対推移ライン（左Y軸）が描画されるか。
- [ ] **テーマタグリンク**: 銘柄名の横に表示されるテーマタグをクリックし、そのテーマのチャートへ遷移するか。

### 3.3 RS/RRG ビュー (`RS View` タブ)
- [ ] **RRG散布図**:
    - [ ] RS-Ratio (X軸) と RS-Momentum (Y軸) に基づき、4象限（Leading/Weakening/Lagging/Improving）に正しくプロットされているか。
    - [ ] 軌跡（Trail）が過去の推移を正しく示しているか。
- [ ] **ミニマップ**: 左側パネルの RS ランク推移グラフが、直近30日間のデータを反映しているか。

### 3.4 スクリーナー (`/screener`)
- [ ] **フィルタリング操作**:
    - [ ] サイドバーの各フィルタ（SMA50乖離、時価総額、RSランク等）を変更した際、即座に、または実行ボタンで結果が更新されるか。
    - [ ] フィルタ条件に合致しない銘柄が排除されているか。
- [ ] **結果テーブル**:
    - [ ] リストされた銘柄のデータ（RS21/63等）が最新の状態か。
    - [ ] テーブルからチャート画面へのリンクが有効か。

---

## 4. データ整合性と例外処理

### 4.1 共通データ検証
- [ ] **数値フォーマット**: ％表示、大きな数値（時価総額等）の単位（B, M）が適切にフォーマットされているか。
- [ ] **日付/時間**: 最終更新日時やチャートのX軸が、ユーザーのローカルタイムゾーンまたは市場のタイムゾーンで整合しているか。

### 4.2 エラーハンドリング
- [ ] **APIエラー**: バックエンドがダウンしている、または 500 エラーを返した際に、適切なエラーメッセージ（トースト等）が表示されるか。
- [ ] **データ欠損 (Empty Data)**: 特定銘柄のデータが DB に存在しない場合、無限ローディングにならず「No Data Available」等の適切な表示がなされるか。
- [ ] **404 Not Found**: 存在しないティッカーの URL に直接アクセスした際、エラーページまたはダッシュボードへのリダイレクトが行われるか。

---

## 5. UI/UX・性能検証
- [ ] **レスポンシブ**: ブラウザの幅を縮小した際、サイドバーが隠れる、またはレイアウトが崩れず操作可能か。
- [ ] **ローディング速度**: ダッシュボードやチャートの初期表示時に、不自然に長い待ち時間が発生していないか。
- [ ] **コンソールエラー**: ブラウザのデベロッパーツール（F12）で、React の Warning や JS エラー、通信エラー (404/500等) が出力されていないか。
